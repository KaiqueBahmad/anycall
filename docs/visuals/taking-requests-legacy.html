How a server took a request, before

Before ae10ab9, servers waited on BRPOP. Redis woke them the instant a request arrived, but the request left Redis the moment it was taken, so a crash lost it without a trace. How it works now.

    The read loop

    1 · Snapshot

    Read the registered methods, and keep only those with a free slot. None registered, or none free: sleep 1s and start over.

    2 · BRPOP, up to 5s

    Block on those methods' queues. Redis hands each new request to exactly one waiting server, the instant it's pushed.

    3 · Dispatch

    Add the id to the in-memory in-flight set and give the request to a worker. Then back to 1.

    Why it changed

    Legacy

    • BRPOP: blocks, no wake needed
    • In-flight set in the server's memory
    • Crash → TimeoutError after 30s (the default)
    • New method or freed slot noticed up to 5s late
    • 3 connections per server

    Current

    • ACQUIRE_SCRIPT: RPOP + HSET, doesn't block
    • anycall:inflight in Redis, read by reaping
    • Crash → ServerLostError in 8–10s (30–60s with no other server)
    • Client publishes a wake; 1s fallback
    • 4 connections per server
